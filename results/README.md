# Results

Everything here is generated by scripts from logged runs; nothing is edited by hand. Figures without data are labelled "pending" templates.

| Path | Made by | Contents |
|---|---|---|
| `metrics/runs.csv`, `metrics/results_table.md` | `scripts/collect_results.py` | One row per run (Table 2): status, steps, final success counts, 95% CI, best eval, backend, commit |
| `metrics/evals.csv` | `scripts/collect_results.py` | Every logged evaluation |
| `metrics/data_efficiency.csv` | `scripts/collect_results.py` | Final success per demo budget, per seed and pooled |
| `figures/fig2_training_loss.{png,pdf}` | `scripts/plot_results.py` | Training loss vs step |
| `figures/fig2b_success_vs_step.{png,pdf}` | `scripts/plot_results.py` | Success during training, one panel per run, 95% CIs |
| `figures/fig3_data_efficiency.{png,pdf}` | `scripts/plot_results.py` | Final success vs number of demos |
| `media/<run>/` | `scripts/export_rollouts.py` | Labelled rollout GIFs, success/failure montage, `rollouts.json` |

## Updating after a run

1. Download the run's small files into `runs/kaggle/` (checkpoints stay there, never committed): `kaggle kernels output <user>/<notebook> -p runs/kaggle_download --file-pattern '(metrics\.jsonl|config\.json|sessions\.jsonl|DONE|\.npz|final\.pt)$'` (needs a Kaggle API token in `~/.kaggle/`), or use the version's Output tab. Copy the small files (not checkpoints) to `results/runs/<exp_name>/`.
2. Regenerate:
   ```bash
   python scripts/collect_results.py results/runs
   python scripts/plot_results.py results/runs
   python scripts/export_rollouts.py runs/kaggle/<exp_name>/checkpoints/final.pt --num-episodes 20 --size 192 --stride 3 --fps 12
   ```
3. Commit `results/` (raw logs, CSV, Markdown, PNG/PDF and a few GIFs; never checkpoints).

## Reporting rules

- The headline number is the **final** model's evaluation of a **completed** run. "Best" evaluations are selected on the test scenes and are reported only as secondary, labelled optimistic.
- Every number carries its trial count (e.g. 52/100) and, where aggregated, its number of seeds.
- Runs with "smoke" in their name are pipeline checks and are excluded unless `--include-smoke` is given.
- Evaluations on different simulator backends (`physx_cuda` on Kaggle, `physx_cpu` on a Mac) are labelled and not pooled.
